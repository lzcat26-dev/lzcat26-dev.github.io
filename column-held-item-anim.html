手持ちアイテムのアニメーションを再生する方法

アニメーション attachable

銃を撃ったときの反動のように、手に持ったアイテム(attachable)で一回だけのアニメーションを動かすやり方です。

スクリプトの playAnimation() で動かそうとして、うまくいかなかった人も多いと思います。

結論

  • 一人称の手持ちアイテムのアニメは、playAnimation() では動かない
  • attachable の中のアニメーションコントローラーで、q.is_using_item などの Molang を合図にして切り替える
  • アイテムには minecraft:use_modifiers をつける。ないと q.is_using_item が true にならない
  • スクリプトの合図で動かしたいなら、武器をプレイヤーのモデルに入れて、プレイヤーのプロパティで切り替える

playAnimation() は使えない

コントローラーの書き方や stopExpression をいろいろ変えて試しましたが、一人称の手持ちアイテムのアニメは、playAnimation() では何も起きませんでした。エラーも出ません。

スクリプトから動かすのはあきらめて、リソースパックの側だけで切り替えます。

1. アイテムに use_modifiers をつける

"minecraft:use_modifiers": {
  "movement_modifier": 1,
  "use_duration": 3
}

これがないと、右クリックしても「使っている」状態にならず、q.is_using_item がずっと false のままです。movement_modifier を 1 にしておけば、使っている間も足は遅くなりません。

2. アニメーションコントローラーを作る

"controller.animation.lzc_gun.shot": {
  "initial_state": "default",
  "states": {
    "default": {
      "transitions": [ { "shot": "q.is_using_item" } ]
    },
    "shot": {
      "animations": [ "shot" ],
      "transitions": [ { "default": "q.all_animations_finished" } ]
    }
  }
}

右クリックで shot に移って一回再生し、終わったら default に戻ります。

default のように何も再生しない状態では、"animations": [] と空で書くと読み込みのときにエラーになります。animations ごと書かないようにします。

3. attachable に登録する

"animations": {
  "first_person_hold": "animation.lzc_gun.first_person_hold",
  "third_person_hold": "animation.lzc_gun.third_person_hold",
  "shot": "animation.lzc_gun.shot",
  "first_person_shot": "controller.animation.lzc_gun.shot"
},
"scripts": {
  "animate": [
    { "first_person_hold": "c.is_first_person" },
    { "third_person_hold": "!c.is_first_person" },
    { "first_person_shot": "c.is_first_person" }
  ]
}

構え(hold)のアニメはずっと動かしたまま、その上にコントローラーを重ねます。

同じボーンを2つのアニメで動かさない

ここがいちばんハマりました。構えのアニメと撃つアニメの両方で同じボーン(たとえば銃全体の root_item)を動かすと、2つの値が足し算されます。上書きではありません。銃が変な角度に飛んでいったり、大きくなったりします。

なので、撃つアニメでは、構えのアニメが動かしているボーンには一切さわりません。スライドや撃鉄のように撃つときだけ動く部品だけを、[0, 0, 0] から動いて [0, 0, 0] に戻る形で書きます。

スクリプトから合図を送りたいとき: プレイヤーのアニメにする

「この技を出したら振る」「弾が0になったらリロード」のように、スクリプトだけが知っている合図は、q.is_using_item のような Molang では調べられません。

そういうときは、武器を attachable ではなくプレイヤーのモデルの中に入れて、プレイヤーのアニメとして動かします。Relic Clash の剣は、全部このやり方です。

  • 剣のモデルは、プレイヤーのジオメトリに入れておく。手に持っているアイテムを query.get_equipped_item_name(0) で調べて、持っているときだけ見せる
  • プレイヤーに client_sync: true の数字のプロパティを作る
  • スクリプトは振るときにそのプロパティを変える。プレイヤーのアニメーションコントローラーが q.property() を見て切り替わる
"relic:sw_swing": {
  "type": "int",
  "range": [ 0, 4 ],
  "default": 0,
  "client_sync": true
}
"holding": {
  "animations": [ "sword_holding" ],
  "transitions": [ {
    "swing1": "q.property('relic:sw_swing') != v.sw_seen && q.property('relic:sw_swing') > 0"
  } ]
},
"swing1": {
  "on_entry": [ "v.sw_seen = q.property('relic:sw_swing');" ],
  "animations": [ "sword_swing1" ],
  "transitions": [ { "holding": "q.all_animations_finished" } ]
}

ポイントは、振るたびに値を 1 と 2 で交互にすることです。同じ値を入れ直しても「変わった」ことにならないので、続けて振ったときに2回目が出ません。コントローラーの側は、最後に見た値を v.sw_seen に取っておいて、それとちがう値が来たら振ります。v.sw_seen には、initialize で先に 0 を入れておきます(理由は下の「気をつけること」)。

const parity = new Map();

function signalSwing(player) {
  const next = (parity.get(player.id) ?? 0) ^ 1;
  parity.set(player.id, next);
  player.setProperty("relic:sw_swing", 1 + next);
}

プレイヤーのアニメなので、一人称と三人称で別々のアニメを用意できます。手持ちアイテムの構えのアニメと同じく、同じボーンを2つのアニメで動かすと足し算になるのは変わりません。

attachable のまま済ませたいなら、リロード中だけ別のアイテム(マガジン)に持ち替えて、そのアイテムの構えのアニメとして動きを出す、というやり方もあります。

気をつけること

スクリプトでクリックを無視しても、アニメは止まりません。アニメは q.is_using_item を見て勝手に動くので、スクリプトの側で「今は撃たない」と決めても、動きだけは出てしまいます。

クリックそのものを止めたいときは、アイテムに minecraft:cooldown をつけて、スクリプトから player.startItemCooldown() を呼びます。こうすると使うこと自体ができなくなるので、アニメも出ません。

pre_animation で、まだ値の入っていない変数を読まない。v.x = 条件 ? q.life_time : v.x; のように自分を読む変数は、initialize で先に値を入れておきます。入れていないとエラーになり、そこから下の pre_animation が全部動かなくなります。私はこれで、銃が全部見えなくなりました。
